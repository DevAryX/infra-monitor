# Docker Setup

This folder contains the Docker and Docker Compose configuration for `infra-monitor`.

Docker packages the Bash monitoring application into a repeatable environment, while Docker Compose runs the complete monitoring stack locally and on the Terraform-managed AWS EC2 host.

## Architecture

```
Docker Compose
├── infra-monitor
│   ├── host-aware Bash report
│   └── custom .prom metrics
├── node-exporter
├── prometheus
└── grafana
```

The `infra-monitor` workload runs the system health report as a one-shot container.

Node Exporter exposes Linux host metrics and the custom `infra_monitor_*` metrics generated by the Bash application.

Prometheus scrapes and stores those metrics.

Grafana provides the provisioned monitoring dashboard.

## Files

```text
docker/
├── Dockerfile
├── docker-compose.yml
└── runtime.env.example
```

### `Dockerfile`

Builds the `infra-monitor` application image from Ubuntu 22.04.

It installs the runtime dependencies required by `system_report.sh`, copies the script into the image, and configures it as the default container command.

### `docker-compose.yml`

Defines the complete monitoring stack:

```text
infra-monitor
node-exporter
prometheus
grafana
```

It also defines the required networks, bind mounts, named volumes, restart behaviour, host visibility, and localhost-only monitoring bindings.

## Runtime Configuration

Safe tracked template:

```text
docker/runtime.env.example
```

Ignored runtime configuration:

```text
docker/runtime.env
```

Create the runtime file with:

```bash
cp docker/runtime.env.example docker/runtime.env
```

The real runtime file is intentionally ignored by Git.

It controls values such as:

```text
CPU threshold
memory threshold
disk threshold
log paths
metrics directory
host root
optional S3 destination
```

Real secrets or machine-specific runtime values should not be committed.

Grafana administrator credentials are stored separately outside the repository:

```text
~/.config/infra-monitor/grafana.env
```

## Host-Aware Monitoring

The `infra-monitor` container intentionally observes the host rather than only its own container namespace.

Compose provides:

```yaml
network_mode: host
pid: host
uts: host
```

and mounts the host filesystem read-only at:

```text
/host
```

This allows the report to inspect the real host:

```text
hostname
operating system
processes
network interfaces
root filesystem
```

The host filesystem mount remains read-only.

The container is also hardened with:

```text
read-only root filesystem
all Linux capabilities dropped
no-new-privileges
```

The workload does not require privileged mode.

## Storage

Application reports are written through:

```text
logs/ → /app/logs
```

Custom Prometheus metrics use the shared Node Exporter textfile volume.

Prometheus stores time-series data in:

```text
prometheus-data
```

Grafana stores runtime state in:

```text
grafana-data
```

The important Grafana datasource and dashboard configuration is also provisioned from Git, allowing the monitoring configuration to be recreated on a fresh host.

## Validate the Compose Configuration

From the repository root:

```bash
docker compose \
  -f docker/docker-compose.yml \
  config --quiet
```

No output means the configuration is valid.

## Build and Run

Build the Infra Monitor image:

```bash
docker compose \
  -f docker/docker-compose.yml \
  build infra-monitor
```

Start the monitoring stack:

```bash
docker compose \
  -f docker/docker-compose.yml \
  up -d --build
```

Inspect all containers, including the completed one-shot Infra Monitor workload:

```bash
docker compose \
  -f docker/docker-compose.yml \
  ps -a
```

Run the monitoring health check:

```bash
bash scripts/monitoring_health_check.sh
```

A healthy stack should finish with:

```text
All monitoring health checks passed
```

## Security

Grafana and Prometheus bind only to localhost on the host.

On EC2 they are accessed through SSH tunnels rather than permanent public monitoring ports.

Runtime secrets are kept outside Git, and the `infra-monitor` container receives only the host visibility required for monitoring.
